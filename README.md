# CenKL traffic replay: what it does and how to run it

This is a small prototype. It takes a **flow**—an ordered list of traffic directions + sizes—and exchanges dummy zero bytes in that order. It can read a JSON flow list, generate a random list, or import a list generated by CenKL. It opens one connection per flow.

**Current TLS record experiment:** Run the client and server with the same flow list and `-tls-records`. The listed size means the full TLS 1.3 record size, including header + encryption overhead. The client sends at client-to-server turns; the server sends at server-to-client turns. The server logs the encrypted record length observed for every turn and checks it against the list. See [DOCKER.md](DOCKER.md) for the two-container setup. Docker uses an internal port; it does not publish the server to the internet.

The earlier discard and `-target-segments` modes remain for comparison.

## Run ordered TLS record replay without Docker

From the repository root, create a local certificate once, then use two Terminal windows:

```sh
mkdir -p work
openssl req -x509 -newkey rsa:2048 -nodes -keyout work/server-key.pem -out work/server-cert.pem -days 1 -subj '/CN=localhost' -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
```

Terminal 1 runs the server with the flow list:

```sh
go run ./cmd/cenkl-discard-server -cert work/server-cert.pem -key work/server-key.pem -input examples/flows.json
```

Terminal 2 runs the client with the **same** list:

```sh
go run ./cmd/cenkl-replay -input examples/flows.json -endpoint 127.0.0.1:9000 -tls -ca-cert work/server-cert.pem -tls-records
```

The example asks for 1,000 and 500 byte client-to-server records followed by a 1,400 byte server-to-client record. The server should log matching `expected_record` and `observed_record` values for all three. It exits after the listed flows finish. The certificate files stay in `work/`, which Git ignores.

## Earlier segment-target experiment

You need Go 1.22 or newer and OpenSSL. Run these commands from the root of this repository.

**1. Create a local test certificate** (once per day; it expires after one day):

```sh
mkdir -p work
openssl req -x509 -newkey rsa:2048 -nodes -keyout work/server-key.pem -out work/server-cert.pem -days 1 -subj '/CN=localhost' -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
```

**2. Start the TLS discard server** in Terminal 1. Leave it running:

```sh
go run ./cmd/cenkl-discard-server -cert work/server-cert.pem -key work/server-key.pem
```

**3. Start the client** in Terminal 2:

```sh
go run ./cmd/cenkl-replay -input examples/client-only.json -endpoint 127.0.0.1:9000 -tls -ca-cert work/server-cert.pem -target-segments
```

[`examples/client-only.json`](examples/client-only.json) asks for client-to-server TCP payload sizes of 1,000 and 500 bytes. With `-target-segments`, the client uses TLS 1.3 and subtracts 22 bytes of TLS overhead from each write. It should print **1,456 application bytes sent** and **1,500 target TCP payload bytes**. The server should print **1,456 bytes received**. These numbers confirm the dummy data crossed the TLS connection. They do not prove the network made 1,000-byte and 500-byte TCP segments; see the capture step below.

Stop the server with Ctrl+C. The certificate and private key stay in `work/`, which Git ignores.

## Try different flow lists

**Edit a list:** Change the directions and sizes in [`examples/client-only.json`](examples/client-only.json), or pass another JSON file with `-input`.

**Generate a random list:** With the TLS server running, replace `-input examples/client-only.json` with the following flags:

```sh
-random -flows 1 -events 10 -min-size 100 -max-size 1500
```

For example:

```sh
go run ./cmd/cenkl-replay -random -flows 1 -events 10 -min-size 100 -max-size 1500 -endpoint 127.0.0.1:9000 -tls -ca-cert work/server-cert.pem -target-segments
```

Random mode saves every generated direction and size to a new `generated-flows-<seed>.json` file and prints its name. Add `-seed 42` to reproduce the same list or `-save NAME.json` to choose a filename. The saved JSON is the **requested flow list**, not a recording of packets observed on the network. Random directions may include server-to-client entries, which the client skips.

**Use CenKL-generated flows:** The `cenkl-import` command converts CenKL's signed-size CSV into this client's JSON format. Follow [CENKL_IMPORT.md](CENKL_IMPORT.md) for the generator and import commands. This is the route toward using model-based traffic shapes rather than uniform random sizes.

## Check the actual TCP segment sizes

CenKL studies the **payload size of each TCP packet** carrying TLS traffic. To see what your local run actually produced, start a capture in Terminal 3 *before* running the client:

```sh
sudo tcpdump -i lo0 -s 0 -w work/tls-capture.pcap 'tcp port 9000'
```

Run the single-flow client from the quick start, then stop `tcpdump` with Ctrl+C. List the captured client-to-server TCP payload sizes:

```sh
./scripts/show-client-segments.sh work/tls-capture.pcap
```

The output has a capture time and payload size for each client segment. The first entries include the TLS handshake. Compare the later data entries with the 1,000 and 500 byte targets. TCP may split or combine writes, so **the captured sizes are the result to trust**. Capture requires permission on the loopback interface. This helper lists observed sizes; it does not automatically match each captured packet to a JSON event.

## Other modes and limits

- Without `-target-segments`, each `size` means **dummy application bytes**, not a target TCP payload size.
- Without `-tls`, the client sends plain TCP. A plain TCP listener such as `nc -l 9000 > /dev/null` can receive it. Use `-tls` and `-ca-cert` together for the included TLS server.
- Target mode supports client-to-server sizes from 23 through 16,406 bytes. Smaller sizes cannot hold the 22-byte TLS 1.3 record overhead plus at least one dummy byte.
- The program does not replay timing, responses, original payloads, or traffic through a proxy. It does not record ISP traffic or run CenKL analysis.

Run the tests with:

```sh

```
